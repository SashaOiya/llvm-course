# Набор инструкций приложения (Задание 4)

Собственный ассемблерный ISA, составленный по статистике задания 2
(`Pass2_trace/reports/report_opt.txt`, динамические доли в -O2) и по IR
приложения `app.c` (диффузия тепла 256x256: 8 подшагов, цвет, simPutPixel).

## Модель машины

- **Регистры**: `x0..x15` — 32-битные беззнаковые (`uint32_t`).
  Значения с плавающей точкой хранятся в регистрах как их битовые
  представления IEEE-754 (как u32).
- **Память данных (DS)**: линейный сегмент 524288 байт (u32-слова),
  байтовая адресация, выравнивание 4:
  - `u`      — смещения `0x0..0x3FFFF`    (256x256 float = 65536 слов)
  - `next_u` — смещения `0x40000..0x7FFFF` (256x256 float = 65536 слов)
- **Поток управления**: безусловный `BR`, условный `BR_COND`, завершение
  `EXIT`. В ASM2IR-генераторе (вариант 1) именно эти три инструкции
  НЕ эмулируются, а переводятся в настоящие IR-переходы.
- **Графические инструкции** (вызовы из статистики `call`, 10.2%):
  `PUT_PIXEL` (→ `simPutPixel`) и `FLUSH` (→ `simFlush`).

## Инструкции

### Целочисленные (i32)

| Инструкция | Семантика | Соответствие IR / статистике |
|---|---|---|
| `MOVi rd, imm`          | `rd = imm` | константы (alpha, 100f, маски) |
| `ADD rd, ra, rb`        | `rd = ra + rb` | `add`, паттерн `add<-phi` |
| `ADDi rd, ra, imm`      | `rd = ra + imm` | инкременты/адреса: `add i32, 1`, `getelementptr<-add` |
| `SUB rd, ra, rb`        | `rd = ra - rb` | упаковка цвета |
| `SUBi rd, ra, imm`      | `rd = ra - imm` | `sub` с константой |
| `MUL rd, ra, rb`        | `rd = ra * rb` | `mul` |
| `MULi rd, ra, imm`      | `rd = ra * imm` | умножение на константу |
| `SHL rd, ra, imm`       | `rd = ra << imm` | `shl` (паттерн #20): `y*1024`, `x*4`, `r<<16` |
| `SHR rd, ra, imm`       | `rd = ra >> imm` | `lshr` (деление на степень 2) |
| `AND rd, ra, rb`        | `rd = ra & rb` | `and` (5.15%): диапазоны квадрата, маски ARGB |
| `ANDi rd, ra, imm`      | `rd = ra & imm` | с константой |
| `OR rd, ra, rb`         | `rd = ra \| rb` | `or`: сборка ARGB |
| `ORi rd, ra, imm`       | `rd = ra \| imm` | с константой |
| `XOR rd, ra, rb`        | `rd = ra ^ rb` | `xor` (утилита) |

### Память

| Инструкция | Семантика | Соответствие |
|---|---|---|
| `LD rd, ra` | `rd = *(u32*)(DS + ra)`; адрес в байтах | `load` (12.76%, паттерны `load<-getelementptr`) |
| `ST ra, rb` | `*(u32*)(DS + ra) = rb` | `store` (5.15%) |

Адрес вычисляется арифметикой выше — это прямой аналог `getelementptr`
(30.70% всех исполнений в -O2): `SHL` на 10 (строка) и 2 (столбец) + `ADD`.

### Вещественные (f32: значения регистров интерпретируются как float)

| Инструкция | Семантика | Соответствие |
|---|---|---|
| `FADD rd, ra, rb` | `rd = ra + rb` (float) | `fadd` (15.32% — сумма соседей) |
| `FSUB rd, ra, rb` | `rd = ra - rb` | `fsub` |
| `FMUL rd, ra, rb` | `rd = ra * rb` | `fmul` |
| `FMULi rd, ra, imm` | `rd = ra * imm` (imm — биты float) | `fmul` с константой (0.01f, 2f, 4f, 255f) |
| `FMULADD rd, ra, rb, rc` | `rd = ra*rb + rc` (float) | `llvm.fmuladd.f32` (`call`, паттерны #17/#18) — формула диффузии `u + alpha*lap` |
| `FTCI rd, ra` | `rd = (int32_t)(float)ra` (trunc) | `fptosi` при отрисовке `(int)(norm*2*255)` |

### Сравнения (результат 1/0 в регистре; знаковые для целых)

| Инструкция | Семантика | Соответствие |
|---|---|---|
| `CMPEQi rd, ra, imm` | `rd = (ra == imm)` | `icmp eq` (границы циклов) |
| `CMPGEi rd, ra, imm` | `rd = (ra >= imm)` | `icmp sge`: `y >= 116` |
| `CMPLTi rd, ra, imm` | `rd = (ra < imm)` | `icmp slt`: `y < 140` |
| `FCMPLTi rd, ra, imm` | `rd = ((float)ra < imm)` | `fcmp olt`: `norm < 0.5f` (цветовая ветка) |

В IR -O2 условия `y>=116 && y<140 && x>=116 && x<140` собираются цепочкой
`icmp`+`and` (паттерны #6/#14/#15) — в ISA это три `CMP*` + `AND`.

### Поток управления и графика

| Инструкция | Семантика |
|---|---|
| `BR L`             | безусловный переход (аналог `br label`, 5.17%) |
| `BR_COND rc, Lt, Lf` | если `rc != 0` → `Lt`, иначе `Lf` (сам `br i1` с условием; `br<-icmp`/`br<-and` — топ паттерны) |
| `EXIT`             | завершение программы (`ret`) |
| `PUT_PIXEL ry, rx, rc` | `simPutPixel(ry, rx, rc)` — вызов графики (3 регистра: y, x, ARGB) |
| `FLUSH`            | `simFlush()` |

Форма `BR_COND rc, Lt` (без `Lf`) означает fallthrough на следующую метку.

## Почему не вошли некоторые IR-инструкции

- `phi` — структурная SSA-конструкция; в регистровой машине значения живут
  в регистрах, отдельная инструкция не нужна.
- `trunc i64 -> i32` (2.59%) — 32-битная ISA, переполнение совпадает
  с усечением; не нужна.
- `memcpy` (паттерн #19, 0.018%) — редкий оптимизирующий ход компилятора;
  копирование поля делается циклом `LD`/`ST`.
- `getelementptr` как таковой — заменён адресной арифметикой
  (`SHL`+`ADD`), см. выше.

## Синтаксис ассемблера

```
# комментарии до конца строки; константы: десятичные или 0xHEX
entry
    MOVi  x4, 0x42C80000     # 100.0f
loop_y
    CMPGEi x5, x1, 140
    BR_COND x5 main_loop loop_x
loop_x
    SHL  x8, x1, 10          # y*1024
    SHL  x9, x2, 2           # x*4
    ADD  x10, x8, x9
    LD   x3, x10
    ...
    ADDi x2, x2, 1
    BR loop_x
exit
    EXIT
```

Метки — отдельной строкой (один токен). Программа — `IRGen/app_asm.s`
(8 кадров: 8x диффузия, копирование, отрисовка). Выполнение:
`app_asm_sim` (чистая симуляция), `app_asm_IRgen_1` (эмуляция вызовами),
`app_asm_IRgen_2` (полные IR-эквиваленты).
