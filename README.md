# llvm-course: визуализация диффузии тепла

## Требования

- clang (LLVM)
- SDL2 (заголовки и библиотека): `sudo apt install libsdl2-dev`

## Сборка

```sh
make
make app        # только обычная сборка
make app-opt    # сборка из оптимизированного IR (-O2)
make app-os     # сборка из оптимизированного IR (-Os)
```

Бинарники складываются в `build/`, промежуточный IR (`.ll`) — в `IR/`.
## Запуск

```sh
./build/app        # обычная сборка
./build/app-opt    # из IR с -O2
./build/app-os     # из IR с -Os
```

## Физический процесс

На экране — численное решение двумерного уравнения теплопроводности
(диффузии):

```
∂u/∂t = α·(∂²u/∂x² + ∂²u/∂y²)
```

В каждый момент времени (фрейм) происходит следующее:

- **Сетка 256x256** — двумерное поле температуры `u`; изначально всё
  поле холодное (`u = 0`).
- **Источник тепла** — стационарный квадрат 24x24 в центре сетки: его
  температура всегда зафиксирована на `u = 100`. Он не остывает и
  постоянно «подогревает» окружающую среду.
- **Диффузия** — за один шаг температура каждой клетки обновляется по
  схеме forward Euler с пятиточечным лапласианом:

  Тепло перетекает из более горячих клеток в более холодные: центральная
  зона греет соседние, фронт тепла плавно расширяется от источника
  к краям, градиент температуры сглаживается.

Визуально видно, как от центрального квадрата расходится волна тепла:
горячая зона расширяется, градиент становится плавнее, пока поле не
выходит в стационарное состояние под постоянным нагревом.

## Генерация LLVM IR

```sh
make IR/app.ll        # IR без оптимизаций (app.c)
make IR/app-opt.ll    # оптимизированный IR, -O2
make IR/app-os.ll     # оптимизированный IR, -Os
```

### Как посмотреть IR

IR — это обычный текст:

```sh
cat IR/app-opt.ll               # вывести весь файл
```

## Очистка

```sh
make clean      # удаляет build/, IR/ и full.bc
```

## Задание 2: трасса использования IR-инструкций (User <- Operand)

Инструментирующий LLVM Pass собирает в рантайме трассу
`(User <- Operand)` для модуля `app.c` на -O2/-Os (phi-инструкции как
User пропускаются) и анализирует частые паттерны длины окна 1–5.
Всё — в `Pass2_trace/`:

```sh
make app-trace-opt app-trace-os  # инструментированные бинарники
make trace-run TRACE_SECONDS=6   # собрать трассы
make trace-report                # отчёты Pass2_trace/reports/
```

Подробности и результаты: `Pass2_trace/README.md`.

## Задание 3: IR-генератор логического модуля + интерпретация в ExecutionEngine

`IRGen/app_ir_gen.cpp` генерирует IR модуля `app.c` вручную через IRBuilder
(глобальные `u`/`next_u`, phi-циклы диффузии, цвета, вызовы `simPutPixel`) — в модуле
только функции, реально вызванные при исполнении: определение `app()` и объявления
внешних графических функций `simPutPixel`/`simFlush`. Далее IR исполняется
интерпретатором LLVM (EngineKind::Interpreter) через `runFunction(app)`; графические
функции пробрасываются на нативные `sim.c` (Interpreter находит их по имени символа
через libffi; бинарь линкуется с `-Wl,--export-dynamic`). Бесконечный `while(1)`
заменён на конечное число кадров (`-DFRAMES`, по умолчанию 1), чтобы интерпретация
завершилась.

```sh
make irgen            # IRGen/app_ir_gen (+build/sim_irgen.o)
make irgen-run        # с окном; закрыть вручную или IRGEN_AUTOQUIT=1
make irgen-run-dummy  # headless: SDL_VIDEODRIVER=dummy + автозакрытие
make irgen IRGEN_FLAGS=-DFRAMES=2   # 2 кадра
```

Проверено: `[VERIFICATION] OK`, defined functions: `app`, external: `simPutPixel simFlush`,
`[EE] app() finished, result: 0`, ~1.7 c/кадр в интерпретаторе (256x256).

## Задание 4: свой ISA, ASM и ASM2IR-генераторы

1) **Свой набор инструкций** — `IRGen/ISA.md`: регистровая машина (x0..x15),
линейный сегмент данных DS (u, next_u), инструкции подобраны по статистике
задания 2 (getelementptr 30.7% -> адресная арифметика, fadd/fmuladd -> FADD/
FMULADD, load/store -> LD/ST, icmp/and/br -> CMP*/AND/BR_COND и т.д.) и по IR
приложения (FTCI, CMPGEi/CMPLTi, FCMPLTi для отрисовки).
2) **Приложение на своём ASM** — `IRGen/app_asm.s` (172 строки): нули,
квадрат-источник, 8 кадров x 8 подшагов диффузии, копирование, отрисовка
с цветами и `PUT_PIXEL`/`FLUSH`/`EXIT`.

**ASM2IR-генераторы** (общий парсер — `IRGen/app_asm_common.h`):
3) `IRGen/app_asm_IRgen_1.cpp` — каждая инструкция -> вызов эмулирующей
функции `do_*` (`IRGen/app_asm_runtime.c`), кроме потока управления
(BR/BR_COND/EXIT -> настоящие IR-переходы); запуск на ExecutionEngine (JIT).
4) `IRGen/app_asm_IRgen_2.cpp` — для каждой инструкции генерируются
IR-эквиваленты (GEP/load/store, битовые операции, f32 через bitcast
i32<->f32, FPToSI, icmp/fcmp с zext); запуск на ExecutionEngine (JIT).
5*) `IRGen/app_asm_sim.cpp` — симуляция без генерации IR: цикл по PC вызывает
те же эмулирующие функции (поток управления исполняется в симуляторе).

```sh
make asm-build        # собрать все три (+ рантайм)
make asm-sim          # п.5*: симуляция
make asm-irgen-1      # п.3: эмуляция вызовами + EE
make asm-irgen-2      # п.4: IR-эквиваленты + EE
make asm-run-dummy    # все три headless
```

Проверено: `[VERIFICATION] OK`; все три варианта дают бит-в-бит одинаковый
результат: `pixels: 524288 (8 кадров), pixel-hash: 0x1a9931984b767925,
data-hash: 0x56ba9ad6a7e3f115`; время (8 кадров): симуляция ~1.6 с,
эмуляция вызовами ~0.8 с, IR-эквиваленты ~0.1 с.
